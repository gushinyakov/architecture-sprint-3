# Задание 1. Анализ и планирование

### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут 
    - удаленно включать / выключать отопление
    - удаленно регулировать температуру
- Система поддерживает
    - взаимодейтсвие с API датчиками температуры (IoT)
    - web интерфейс для усправления датчиками температуры

**Мониторинг температуры:**

- Пользователи могут
    - просматривать текущие состояние датчиков температуры (вкл/выкл, температура)
- Система поддерживает
    - взаимодейтсвие с API датчиками температуры (IoT)
    - web интерфейс для просмотра состояния датчиков температуры


### 2. Анализ архитектуры монолитного приложения

- *Язык программирования:* Java
- *База данных:* PostgreSQL
- *Архитектура:* Монолитная, все компоненты системы (обработка запросов, бизнес-логика, работа с данными) находятся в рамках одного приложения.
- *Взаимодействие:* Синхронное, запросы обрабатываются последовательно.
- *Масштабируемость:* Ограничена, так как монолит сложно масштабировать по частям.
- *Развёртывание:* Требует остановки всего приложения.

### 3. Определение доменов и границы контекстов

    - Контекст: просмотр состояния датчиков температуры (вкл/выкл, температура)

#### TO BE

- Домен: Клиент-Пользователь
    - Поддомен: Управление профилем
        - Контекст: Редактирование профиля
    - Поддомен: Управление устройствами
        - Контекст: Задание правил/предпочтений для устройств\
        (поддержание температуры в доме 28 градусов)

- Домен: Клиент-Администратор
    - Поддомен: Управление профилем
        - Контекст: Редактирование профиля
    - Поддомен: Обработка заявок
        - Контекст: Обработка жалоб пользователя
        - Контекст: Обоаботка заявок на подключение устройств  

- Домен: Клиент-Тех специалсит
    - Поддомен: Управление профилем
        - Контекст: Редактирование профиля
    - Поддомен: Обработка заявок
        - Контекст: Обработка заявок на подключение / диагностику устройств  

- Домен: Управление устройствами
    - Поддомен: Управление командами
        - Контекст: Проверка валидности команд (guard)
        - Контекст: Отправка команд в шину данных (topic: device-command)
    - Поддомен: Перечень устройств (inventory)
        - Контекст: Добавление / удаление устройств
        - Контекст: Перепрошивка устройств

- Домен: Телеметрия устройств
    - Поддомен: Обоботка телеметрии
        - Контекст: Подписка на необработанную телеметрию с устройств из шины (topic: device-raw-tm)
        - Контекст: Обработка телеметрии на основе текущей прошивки
        - Контекст: Отправка обработанной телеметрии в шину (topic: device-tm)
    - Поддомен: Хранение телеметрии
        - Контекст: Подписка на обработанную телеметрию из шины (topic: device-tm)
        - Контекст: Event Storage для записи телеметрии

- Домен: Мониторинг телеметрии
    - Поддомен: Просмотр телеметрии
        - Контекст: Отображение текущих состояний приборов
    - Поддомен: Автоанализ телеметрии
        - Контекст: Автопроверка на валидность текущих значений 
        (автокорректировка невалидных значений - выключение прибора/перезагрузка)
    - Поддомен: Аналитика
        - Контекст: Агрегация телеметрии для построения комплексных дашбордов

- Домен: Связь с устройством
    - Контекст: связь с физическим устройством
    - Контекст: отправка данных в шину (topic: device-raw-tm)
    - Контекст: прием команд из шины (topic: device-command)

### **4. Проблемы монолитного решения**

С получением тендера увеличивается кол-во потенциальных пользователей и функционала.\

- Трудно масштабировать отдельные компоненты системы\
С ростом числа пользователей, часть функций умного дома будут испытвать бОльшую нагузку, чем остальные\
чтение телеметрии\
отправка заявок/жалоб от пользователей\
и тд\
Монолит можно масштабировать только целиком\

- Трудно обновлять технологический стек\
Увелечение перечня устройств скорее всего приведет к расширению необходимого стека\
Будут необходимо специфичные библиотеки, БД, протоколы взаимодействия с устройствами или даже языки програмирования\

- Увелечение сроков тестирования и потенциальных ошибок 
При добавление нового типа устройств или просто изменение текущих, придется тестировать весь функционал умного дома

- Сроки обновления
Выпуск нового релиза озночает обнолвение всего умного дома.
например обновление картоки профиля пользователя будет влиять и на релиз приборов

- Конкурентоспособность
пользователи могут взаимодействовать только через web
скорее всего в дальнейшем часть устройств будет поддерживать bluetooth соедение, 
что сделать через web будет проблематично или невозможно
